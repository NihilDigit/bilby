# Bilby

[English](README.md)

一个拿掉了推荐机制的 bilibili 安卓客户端。

首页只有关注的人的更新，按时间排，翻到底就没有了。底下不会再长出东西来。没有推荐流，
没有相关推荐，没有自动连播。

凡是原本会把下一个视频递到你手上的地方，现在都要你自己选。官方 app 放相关推荐的位置，
Bilby 放的是当前视频所在的合集和这位 UP 的其它投稿——一个你打开这个视频时就已经选定的
有限集合。用它组成的播放队列播到最后一条就停，不回绕、不循环、不从推荐池续接。队列一旦
会自动续上，"要不要接着看"这个决定就被悄悄取消了。

想看别的就说出来。搜索照常用，另外有一个助理可以直接描述：它去搜索、读简介和评论，
然后给你几个视频，每个附上理由。它拿不到你的观看历史，以后也不会给它。它的上下文里
只有你这次说的话。

Bilby 跟 bilibili 之间没有对抗。历史记录、心跳、投币、收藏、点赞都照常上报，拿掉的只是
反过来推你的那部分。

## 功能

关注动态、搜索、稍后再看、UP 空间。

播放支持全屏、切清晰度、倍速、长按快进、拖动进度、锁定、双击暂停、分 P。听视频用另一套
界面接同一个播放器，可以息屏后台放，带播放队列、随机播放和定时关闭。SponsorBlock 的赞助
片段默认跳过。

评论可以看、排序、展开楼中楼、发送、点赞、删除。

## 安装

```
./gradlew installDebug
```

用 TV 端扫码登录，一个账号，扫一次。

助理需要一个 OpenAI 兼容的接口。debug 版可以写在 `local.properties` 里，任何版本也都能在
设置页里填：

```properties
LLM_BASE_URL=https://.../v1
LLM_API_KEY=sk-...
```

需要 Android 10 及以上。技术栈是 Compose、Material 3、Navigation 3、Media3、Room、Ktor。

## 参与

Bilby 是个人项目，只是顺便开源。它现在的样子来自一个人对视频客户端该怎么行事的看法，
而这个看法正是这里要维护的东西。

修 bug、报崩溃、改小错误，直接提 PR。

加功能和改行为要先写 RFC：开一个 issue，说清你想要什么、现在的实现对这件事是怎么处理的、
你设想的方案长什么样，达成一致之后再动手写代码。开头那几条约束是最容易被动到的地方，
没有经过 RFC 就改动它们的 PR，仅凭这一条就会被关掉。

`CLAUDE.md` 里是动手前值得先知道的那些约定。
